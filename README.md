# CORP Desk — Windows-style IT Training Desktop

**Created by Erick Omari · Pitchiluxe**

Double-click **Start-Here.html** for the animated introduction and entry page, then select **Enter the lab**. **Open-Lab.html** still opens the practice desktop directly. Enter a display name and select **Sign in**. No installation or server is required for browser-based practice.

For the installable Windows version, use **dist/downloads/CORP-Desk-Setup.exe**. It installs per user, includes an uninstaller and Start menu entry, and offers an optional desktop shortcut. This is an unsigned preview build. Microsoft Edge WebView2 Runtime is required; the .NET runtime is bundled.

The lab's admin tools are a simulator, not Windows, a VM, RSAT, or real Active Directory. Practice PowerShell never executes arbitrary host commands. The Windows app additionally provides a real Chromium WebView2 browser window and a narrow native connection to your local Ollama service.

## Landing page and Windows app

- `dist/index.html` is the landing page with animated directory, DNS, and ticket workflows. Animation has a pause control and respects reduced-motion preferences.
- `dist/lab.html` is the working simulator. The landing-page launch buttons lead there. The sign-in screen links back to the overview.
- `Start-Here.html` and `Open-Lab.html` are self-contained browser copies generated by `node package.cjs`.
- `windows-app/` contains the WinForms/WebView2 source, multi-resolution icon build, and Inno Setup installer definition. Build with `windows-app/build.ps1` using .NET 10 SDK and Inno Setup 6.
- The installed app loads local assets through WebView2 virtual-host mapping. It needs no Node installation, localhost server, or free TCP port.
- Its browser opens real HTTP(S) pages in a native WebView2 window, including address/search navigation, tabs, back/forward, reload, and normal website context menus. Some websites or sign-in providers can restrict embedded browsers; the external-browser button remains available. It is Chromium-based, not a bundled copy of Google Chrome.
- Local Ollama discovery checks `127.0.0.1:11434`, lists downloaded local models, and distinguishes an installed-but-stopped app. The status button can open a known installed Ollama app at the user's request. No model is downloaded automatically. Chat and generated tickets use native messaging in the Windows version, avoiding page CORS/port issues.
- Normal application data lives in `%LOCALAPPDATA%\Pitchiluxe\CorpDesk`. Uninstalling the app does not silently erase this training/browser data. Developer preview can use `CorpDesk.exe --profile <folder>` to keep its data inside the checkout.
- The custom icon is in `dist/assets/corpdesk.ico` (seven sizes) and `corpdesk.png`; the source generator is `windows-app/build-icon.ps1`.

The local landing-page download is backed by the actual installer, with version, size, and SHA-256 in `dist/downloads/release.json`. Installer binaries are excluded from Git source. ## Active Directory Users and Computers

The MMC-style console has a domain/container/OU tree, sortable object list, toolbar, Action/View menus, and object context menus. It supports finding objects; creating users, groups, and OUs; copying user templates; enabling/disabling/unlocking users; a simulated password reset; membership changes and group nesting; moving objects; renaming eligible objects; protected-OU checks; deletion/recovery; and list export.

User properties include General, Address, Account, Profile, Telephones, Organization, and Member Of. View → Advanced Features adds read-only Object and Attribute Editor tabs. Group properties include scope/type, description, Members, and Member Of. Computer properties show identity, OS, membership, and placement. Profile paths are stored as metadata; no actual profiles are created. Built-in groups are read-only.

Full schema editing, ACL delegation/enforcement, replication, trusts, Kerberos, Exchange, certificates, and legacy RDS options require actual Windows/AD DS and are not implemented. Reset Password validates an invented lab password in memory and discards it. Do not enter a real password.

## PowerShell

Enter `help`, `Get-Command`, or `Get-Help Get-ADUser` for supported syntax. There are 99 documented command entries plus common aliases. The parser supports named/reordered parameters, quoted values, simple variables/property reads, semicolon-separated statements, object pipelines, simple filters, selection, sorting, formatting, CSV operations, and `-WhatIf` for supported mutations.

```powershell
Get-ADUser -Filter * | Select-Object Name,SamAccountName,Enabled
Get-ADUser -Filter * | Where-Object { $_.Department -eq 'HR' }
$employee = Get-ADUser hr01 -Properties *
$employee.LockedOut
Unlock-ADAccount -Identity hr01
Get-ADGroupMember GG_Finance_Staff
Remove-ADGroupMember GG_Finance_Staff -Members hr03 -Confirm:$false
Get-ADComputer LAB-PC01 | Move-ADObject -TargetPath 'OU=Workstations,OU=Lab,DC=corp,DC=example,DC=test'
gpupdate /force
gpresult /r
Get-ADUser -Filter * | Select-Object Name,Department | Export-Csv C:\Lab\users.csv -NoTypeInformation
Import-Csv C:\Lab\users.csv | Measure-Object
```

Tab completes unambiguous command names; Up/Down recalls history. This is a documented subset, not the complete PowerShell language/runtime. Arbitrary scripts, binaries, remoting, complex expressions, full parameter sets, and host filesystem/network access are unavailable. Unsupported commands report errors. Service-inventory changes do not affect real or modeled DC/network services. Complete compatibility requires a real Windows VM.

## Chatbot and optional local Ollama

Open **IT Assistant**. Offline coaching works immediately without a model and is labeled **OFFLINE TRAINING COACH**. It can guide the active incident, review simulator evidence, and explain desktop controls.

To use an actual local model:

1. Start Ollama on your real computer and download a model, for example `ollama pull llama3.2:3b`.
2. Run **Start-Lab.cmd** and keep its terminal open. This starts the loopback-only server at `http://127.0.0.1:8765`.
3. Open that URL in your browser. In IT Assistant → Settings, choose **Local Ollama**, use **List downloaded models**, and enter an exact listed model tag.
4. Send a message. The local server forwards it only to Ollama at `127.0.0.1:11434`; it does not use a cloud endpoint or download a model automatically.

You can also reach assistant configuration from Settings → Home → Your IT assistant. Connection/model errors are shown explicitly. Real model inference was not verified on this computer; the bridge routes were tested with a mock upstream.

## Window sessions, desktop mouse controls, and profile picture

Opening sizes are app-specific and bounded to the viewport: Explorer 980×640, ADUC 1000×660, PowerShell 850×520, Chrome-style browser 1100×740, and chat 550×660, for example. Windows applications do not share one universal default size; these are familiar practice defaults. Reopening a closed app starts at its default size; minimizing preserves its current window/session.

Close now destroys the app window. PowerShell closes its transcript, history, variables, and working directory; its command evidence remains in the exported audit. Chrome closes its tabs/session. Notepad++ and Office practice apps reset their working sessions, asking before discarding marked unsaved edits. Saved virtual files, AD objects/changes, profile preferences, ticket records, and completed lab work remain durable. Closing an AD console does not erase its users or OUs.

Right-click the desktop → **View** for small/medium/large icons, auto arrange, align to grid, and show/hide desktop icons. Ctrl+mouse-wheel over the shortcuts changes icon size. Turn Auto arrange off to drag shortcuts freely; Align icons to grid controls snapping. Ctrl+click selects multiple shortcuts, Ctrl+A selects shortcuts, and Shift+F10 opens a context menu. **Sort by**, New Folder/Text Document, Display settings, and Personalize are available. New files/folders are created in the virtual Desktop folder, accessible through Explorer.

Right-click the taskbar background for **Task Manager**, **Taskbar settings**, and training additions for Show desktop, Cascade windows, and restoring pins. Right-click a pinned app for open, reset size, unpin, and close; Chrome also offers New tab. Task Manager lists and closes only simulator windows. It does not inspect or terminate real Windows processes.

Change the training account picture by clicking the sign-in avatar or through Settings → Accounts/Home → **Change picture**. The selected local JPEG/PNG/WebP is cropped into a small browser-local thumbnail. Your real Windows profile is unchanged.

Chrome-style tabs include right-click duplicate/close/close-other/reopen actions, session history, zoom, and a menu. Common Ctrl+L/T/W/Shift+T/H/J shortcuts are handled where the host browser permits interception. The real browser may reserve these shortcuts. External websites still use an explicit real-browser link; this app is not a Chrome runtime.

## Generate ongoing IT support scenarios

In **Service Desk**, select **Generate practice tickets**. The same control is available in IT Assistant.

1. Choose **Offline scenario variations** or **Local Ollama**.
2. Choose a category, difficulty, and 1–10 tickets for this batch.
3. For Ollama, run Start-Lab.cmd and Ollama, and select an exact downloaded model tag. Restart an older lab server before using updated API features.
4. Generate, open Service Desk, and work the new requests. Generate further batches whenever needed. There is no fixed five-ticket limit; browser storage remains finite.

The catalog spans identity/AD, MFA, DNS, DHCP, Wi-Fi, VPN, file access, Outlook, Teams, OneDrive/SharePoint, printers/scanning, GPO/Windows updates, applications, browser/certificates, security/phishing, BitLocker, hardware, performance/storage, backup/recovery, joiner/mover/leaver, remote support, telephony, mobile devices, and asset management. It covers common daily work, not every possible issue or vendor system.

Generated requests include symptoms, requester, environment, impact, evidence to collect, expected outcome, and validation steps. A collapsed instructor debrief contains the proposed root cause. They are explicitly **manual/tabletop scenarios** and do not silently inject executable faults. The original five exercises retain automatic injection and state checks. Ask IT Assistant to discuss a generated ticket from its brief. Offline scenarios are labeled offline; Ollama output is validated, and model/network failures are not relabeled as successful AI generation.
